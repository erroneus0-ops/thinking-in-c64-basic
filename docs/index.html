A Maze in Two Lines

Before anything else, let’s make the C64 do something worth seeing.

Click the C64 screen. Type these two lines exactly as shown, and press RETURN at the end of each one. Keep Caps Lock off: type ordinary small letters, and the C64 will show them as capitals.

10 PRINT CHR$(205.5 + RND(1));
20 GOTO 10

Now type this and press RETURN:

RUN

A maze fills the screen, row after row, and never stops. Stop it and run it again, and you get a different maze. (There’s a surprise hiding in that word “random”, which Chapter 3 will let you discover for yourself.)

To stop it, press RUN/STOP. On a PC keyboard, that’s Esc. The C64 answers BREAK IN 10 (or 20) and READY.

Right now this probably looks like magic. It isn’t. Every piece has a meaning, and this book teaches you each one:

Piece What it does Taught in
10 and 20 Line numbers: the order of the steps Chapter 2
PRINT Puts something on the screen Chapter 1
; Keeps the next thing on the same row Chapter 1
RND(1) Picks a random number Chapter 3
CHR$( ) Turns a number into a character Chapter 4
GOTO 10 Jumps back to line 10 Chapter 9

When you finish Chapter 9, come back to this page. You’ll be able to explain every character in it.

Programmers sometimes squeeze this same maze into a single, very short line, as a kind of puzzle. It works, but it’s hard to read. This book always writes programs to be read, because a program you can read is a program you can fix.

How This Book Works

This book teaches you to program the Commodore 64. It also teaches something bigger: how to plan, how to keep things in order, and how to break a big job into small ones. Programmers call that organized thinking. The C64 is a good place to learn it, because its BASIC gives you almost no help. Any order in your program has to come from you.

What you need

  • An emulated C64. This book uses VICE, either on your computer or in the browser.
  • A paper notebook and a pencil. This is your programmer’s notebook. You will draw tables and maps in it before you type.
  • About thirty minutes. Every lesson fits in one sitting.

How every lesson goes

Every lesson has the same seven steps, so you always know where you are:

  1. Goal: what you will be able to do by the end.
  2. Picture: a drawing of the idea.
  3. Try it: type something short and run it.
  4. Predict: change one thing, write down what you think will happen, then run it.
  5. Why it works: a short explanation.
  6. Organize it: one habit to add to your notebook.
  7. Exercises and quiz: practice, then five quick questions.

Getting a prediction wrong is not a failure. It’s how you find out what the computer really does. Error messages are normal too. Every chapter makes at least one on purpose.

Chapter 1: This Is a Variable

In this chapter you type commands and press RETURN, and the C64 does them right away. This is called direct mode. You won’t need line numbers until Chapter 2.

Lesson 1.1 — Boxes with labels

Goal: Put a number into the computer’s memory and get it back.

Picture: Imagine a shelf in a garage or a storeroom. On it sits a row of boxes. Each box has a label stuck on the front, so you can find it again without opening every box. Each box holds one thing. A labelled box on the shelf is called a variable. The computer’s memory is a very long shelf with thousands of these boxes.

If you play video games, you already know variables. Your coin counter is a box labelled COINS. Every time you pick up a coin, the game opens that box, adds one, and puts the new number back.

     A           B           C          <- labels
  +-----+     +-----+     +-----+
  |  7  |     |  0  |     |  0  |       <- what is inside
  +-----+     +-----+     +-----+
=======================================  <- the shelf

Try it. Type each line and press RETURN after it:

A = 7
PRINT A

The C64 answers 7. You put 7 into the box labelled A, then asked to see what was inside.

Predict. Before typing the next lines, write down what you think the C64 will show. Then try it.

A = A + 1
PRINT A
PRINT B

Why it works. The = sign does not mean “is equal to” here. It means “put into.” A = A + 1 means: look in box A, add one, and put the answer back in box A. So A now holds 8. Box B was never filled, so it holds 0. On the C64, an empty number box always starts at 0.

That is exactly the coin counter from a game. A = A + 1 is picking up one coin.

You may have noticed a space before each number. The C64 leaves room in front of every number for a minus sign, even when there isn’t one.

Want to know a secret? Type ? instead of the whole word PRINT, and you get the same thing, quicker.

Think of PRINT as a “what is?” command: you ask, and the C64 answers with what it is. So to ask “what is in A?”, you can type:

? A

To make the answer more meaningful, add a word after it:

? A "APPLES."

The C64 answers 8 APPLES. And if you use ? inside a program, LIST shows it spelled out as PRINT, because to the C64 they’re the same word.

Lesson 1.2 — Numbers and words

Goal: Store words as well as numbers.

Try it:

N$ = "KAITO"
PRINT N$
PRINT "MY NAME IS ";N$

A label that ends in a dollar sign holds text (programmers call text a string). The text goes inside quotation marks. The semicolon in the last line glues two things together on the screen.

Think of two kinds of box on the shelf. A coin box holds amounts you can count and add. A note box holds a piece of paper with writing on it. You can’t add two notes together the way you add coins, and you can’t put a note in a coin box.

Predict, then try:

A = "HELLO"

Why it fails. The C64 answers ?TYPE MISMATCH ERROR. Box A is a number box, and “HELLO” is not a number. The label tells the C64 what kind of box it is:

Label looks like Box holds Example
A, PR, X1 Any number, including decimals PR = 23.45
N$, PY$ Text, up to 255 characters N$ = "KAITO"
C%, Q% Whole numbers only, from −32768 to 32767 C% = 3

You will not need the % kind until much later. It is here so the table is complete.

Try it. The same letter can label two different boxes:

A = 5
A$ = "MILLION DOLLARS"
PRINT A;A$

The C64 answers 5 MILLION DOLLARS. A and A$ are two separate boxes, one holding coins and one holding a note. The dollar sign is part of the label, so they never get mixed up.

Lesson 1.3 — The two-letter trap

Goal: Learn the C64’s naming rules, including the strange ones.

Try it:

PRICE = 50
PRIZE = 3
PRINT PRICE

Predict before you run the last line. Most people expect 50. The C64 prints 3.

Why. The C64 only reads the first two letters of a variable name. To the computer, PRICE and PRIZE are both just PR: the same box. The second line quietly replaced the 50. Nothing warned you. Lesson 1.5 shows how to make sure it never happens to you.

Prove it. Ask the C64 what’s in all three names:

? PRICE
? PRIZE
? PR

All three answer 3. Three names, one box.

Picture it this way: the C64 makes its labels with a label maker that can only print two letters. You ask for a label that says PRICE, and the machine prints PR. Later you ask for PRIZE, and it prints PR again. Now the shelf has one box with the label PR, and both names lead to it.

Lesson 1.4 — Words the C64 has already claimed

Goal: Know which names are taken, so you can pick names without worrying.

Picture: Usernames in an online game. When you sign up, some names are already taken, and the game won’t let you have them. The C64 has about seventy words it has already claimed for itself: its commands and functions, like PRINT, GOTO and RUN. Programmers call them reserved words. Appendix E lists every one.

Predict. Will this work? Write down yes or no, then try it:

GOLD = 100

Why it fails. The C64 answers ?SYNTAX ERROR. When you press RETURN, the C64 reads your line looking for its own words, and it finds them even in the middle of a name. Hidden inside GOLD is GO, as in GO TO. The C64 sees GO and can’t make sense of the rest.

The fix is easy: pick a name with no hidden word. GLD = 100 works, and so does GD = 100.

Plenty of good names have a reserved word hiding inside:

Name Hidden word
GOLD GO
LIFE IF
SCORE OR
MONEY ON
TOTAL TO
COST COS
FRIEND END
LENGTH LEN
FORMAT FOR
STATUS ST
TIME TI

That list can make names feel like a minefield. They aren’t. Three facts turn it into a map:

  1. Inside quotes, nothing is reserved. PRINT "GOLD, LIFE AND SCORE" works perfectly. The C64 only hunts for its words outside quotes.
  2. You almost always find out right away. A name with a reserved word inside usually stops with an error the moment you press RETURN, so you fix it and move on. (There’s one sneaky exception, in the box below.)
  3. Two-letter names are safe, with just eight exceptions. The C64 only reads the first two letters of a name anyway, and only eight pairs are taken:
Taken pair Why
IF, ON, OR, TO, GO, FN They’re reserved words themselves
ST, TI They’re the C64’s own boxes (ST reports on disks and tapes; TI is its clock)

Any other two letters can never contain a reserved word. HP, XP, GD, SC, PR: all safe.

Here’s the sneaky one. A name like TITLE$ starts with TI, so to the C64 it’s TI$, the clock shown as hours, minutes and seconds. TITLE$ = "MY GAME" gives ?ILLEGAL QUANTITY ERROR, which at least warns you. But TITLE$ = "120000" gives no error at all: it quietly sets the clock to 12:00:00. Names that start with TI or ST are best avoided completely.

The rules for names, all in one place:

  • A name starts with a letter. After that, letters and digits are allowed.
  • Only the first two characters count.
  • A name must not contain a reserved word.
  • Two-letter names are always safe, except IF, ON, OR, TO, GO, FN, ST and TI.

Lesson 1.5 — Organize it: the variable dictionary

Goal: Start the habit that keeps every program in this book under control.

Because the C64 will not warn you when two names collide, you need a written list of every variable a program uses. This is your variable dictionary. Start a page in your programmer’s notebook like this:

Name Kind What it holds Example
A Number Practice box from Lesson 1.1 8
N$ Text My name KAITO
PR Number Price of one item, in dollars 50

Notebook rule 1: Before you use a new variable, write it in the dictionary. If its first two letters match one already there, or it’s one of the eight taken pairs, pick a different name. Short names are fine: the dictionary is where you write down what they mean.

When a box holds an amount, write its unit in the dictionary too. Is PR the price in dollars or in cents? The number 50 means something very different in each. Later in this book, money is always stored in cents, and the dictionary is where you say so.

In 1999, a spacecraft called the Mars Climate Orbiter was lost at Mars. One team’s program measured thruster force in one unit, and another team’s program read those numbers as a different unit. Every number was right. Nobody had written down which units they were in.

Exercises

  1. Type and predict. Put your age into a variable and your favorite number into another. Before printing their sum, write down what it will be.
  2. Fix it. This set of commands does not work. Find both problems, explain each in one sentence, and fix them: MONEY = 40, then TOTAL = MONEY + 10.
  3. Build it. Using three variables (your name, a game you like, and how many hours you have played it), make the C64 print one sentence about you. Add all three to your variable dictionary first.

Quiz

  1. After A = 5 and then A = A * 2, what does PRINT A show? (a) 5 (b) 7 (c) 10 (d) An error.
  2. What does PRINT Q show if Q was never used? (a) Nothing (b) 0 (c) ?SYNTAX ERROR (d) Q.
  3. Which variable can hold the word HELLO? (a) H (b) H% (c) H$ (d) Any of them.
  4. Which of these names is always safe? (a) GOLD (b) HP (c) IF (d) TITLE$.
  5. A program uses COUNT and CODE. What goes wrong? (a) Nothing (b) They share one box, CO (c) CODE is a command (d) ?TYPE MISMATCH ERROR.

Chapter 2: Talking to the Computer

In Chapter 1, the C64 did each thing the moment you pressed RETURN. Now you’ll learn to give it a list of steps to do later, in order, as many times as you like. That list is a program.

Lesson 2.1 — Now or later

Goal: Tell the C64 to do something now, or save it for later.

Picture: A recipe card. Reading a recipe card doesn’t cook anything. You write the steps down first, then follow them when it’s time to cook. A video game level works the same way: the level is built in advance, and it plays out when you press Start.

Try it. Type this and press RETURN:

PRINT "HELLO"

The C64 prints HELLO straight away. That’s direct mode, the way you worked in Chapter 1.

Now type this, with a number in front, and press RETURN:

10 PRINT "HELLO"

Predict. Before you look, write down what you think happened.

Why it works. Nothing was printed. The number at the start told the C64: don’t do this now, store it as line 10 of a program. That’s program mode. To follow the stored steps, type:

RUN

Now HELLO appears. To see the stored program, type:

LIST

Lesson 2.2 — Lines know their places

Goal: Understand how line numbers keep a program in order.

Try it. Type these three lines in this exact order:

NEW
30 PRINT "THIRD"
10 PRINT "FIRST"
20 PRINT "SECOND"

NEW erases any program already stored, so you start clean.

Predict. You typed 30, then 10, then 20. What order will LIST show? What will RUN print? Write both down, then try them.

Why it works. The C64 files every line by its number, no matter what order you typed it in, like index cards sorted in a box:

  You typed:            The C64 keeps:
  30 PRINT "THIRD"      10 PRINT "FIRST"
  10 PRINT "FIRST"  ->  20 PRINT "SECOND"
  20 PRINT "SECOND"     30 PRINT "THIRD"

RUN always starts at the lowest number and works upward.

Notice the gaps: 10, 20, 30, not 1, 2, 3. If you later need a step between FIRST and SECOND, there’s room for it:

15 PRINT "ONE AND A HALF"

LIST it and see where it went. Line numbers can be anything from 0 to 63999, so there’s plenty of room.

Some later versions of BASIC have a command that renumbers a whole program for you. The C64’s BASIC doesn’t. If you number by ones and run out of room, you have to retype lines. Numbering by tens is how C64 programmers avoid that.

Lesson 2.3 — Changing your mind

Goal: Replace, remove, and look at parts of a program.

Try it. With the four-line program from Lesson 2.2 still stored, type:

20 PRINT "SECOND, CHANGED"

Predict, then LIST it.

Why it works. A line with a number that already exists replaces the old line. The C64 keeps only one line 20.

Now type just the number, and press RETURN:

15

LIST again. Line 15 is gone. A line number with nothing after it removes that line.

When programs get long, you won’t want to see all of it at once. LIST can show part of a program:

You type The C64 shows
LIST Every line
LIST 20 Only line 20
LIST 10-20 Lines 10 through 20
LIST -20 Everything up to line 20
LIST 20- Line 20 and everything after it

RUN can start partway through, too: RUN 20 starts the program at line 20 instead of at the beginning.

And NEW erases the whole program. There’s no undo, so be sure before you use it.

Lesson 2.4 — Fixing a line on the screen

Goal: Fix a mistake without retyping the whole line.

Try it. Type this program, mistake included:

NEW
10 PRINT "MY FAVORITE GAME IS"
20 PRNT "CHESS"
30 PRINT "I PLAY IT A LOT"
RUN

The C64 prints the first line, then stops with ?SYNTAX ERROR IN 20. Helpfully, it tells you which line has the problem. (Yes, the C64 really does print two spaces before the word ERROR.)

Why it works. PRNT isn’t a word the C64 knows. You could fix it by retyping all of line 20. But there’s a faster way, because the C64 lets you edit anything on the screen:

  1. Type LIST so line 20 is on the screen.
  2. Use the arrow keys to move the cursor up to line 20, and right until it’s on the N of PRNT.
  3. Type INT. Each letter you type replaces the one under the cursor, so N, T and the space become I, N and T. The line now reads 20 PRINT"CHESS". The space is gone, but that’s fine: the C64 doesn’t need spaces between words.
  4. Press RETURN while the cursor is anywhere on that line.

When you press RETURN, the C64 reads the whole line from the screen and stores it, exactly as if you had typed it fresh. LIST and RUN to check.

A single program line can be at most 80 characters, which is two rows of the screen. Long lines are also hard to read, so this book keeps them short.

Lesson 2.5 — Organize it: plan, then number

Goal: Start every program on paper, not on the keyboard.

A program is a list of steps in order. Before you type, write the steps in your notebook in plain words, one per line, the way you’d write a recipe. Then give each step a line number, counting by tens.

Step in plain words Line
Show a title 10
Show my name 20
Show my favorite game 30

Now the typing is just copying, and the thinking is already done.

Notebook rule 2: Plan the steps on paper first, in order. Number the lines by tens, so there’s always room to add a step later.

Exercises

  1. Predict the order. Type NEW, then these lines in this order: 40 PRINT "D", 20 PRINT "B", 10 PRINT "A", 30 PRINT "C". Before typing LIST and RUN, write down what each will show.
  2. Fix it two ways. Type the CHESS program from Lesson 2.4. Fix line 20 once by retyping the whole line, then break it again and fix it with the screen editor. Which way was faster?
  3. Build it. Plan a program on paper that shows three facts about you, one per line, using variables from your variable dictionary. Number the lines by tens, type it, and run it. Then add a title line at the top without retyping anything else.

Quiz

  1. You type 10 PRINT "HI" and press RETURN. What happens? (a) HI appears (b) The line is stored and nothing is printed (c) ?SYNTAX ERROR (d) The program runs.
  2. You type lines 30, then 10, then 20. What does LIST show first? (a) Line 30 (b) Line 10 (c) Whichever you typed last (d) Line 20.
  3. What does typing 20 by itself and pressing RETURN do? (a) Runs line 20 (b) Lists line 20 (c) Removes line 20 (d) Nothing.
  4. Why number lines 10, 20, 30 instead of 1, 2, 3? (a) The C64 requires it (b) It leaves room to add lines in between (c) It runs faster (d) It saves memory.
  5. Which command erases the whole program? (a) LIST (b) END (c) CLR (d) NEW.
