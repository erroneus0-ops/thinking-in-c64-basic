Foreword

This book teaches you to program a computer from 1982: the Commodore 64. That might seem like a strange choice. The phone in your pocket is many thousands of times more powerful, and today’s programming languages can do far more, far more easily. So why start here?

Because programming isn’t really about the language. It’s about thinking. Before a good programmer types anything, they work out what the program needs to do, break the job into small steps, and decide where everything will go. Only then do they write the code. Plan, organize, then code. That habit works the same way in every programming language ever made, and it’s what this book is really about.

The C64 is a great place to learn it, because it gives you almost no help. Its BASIC won’t fix your mistakes, tidy up your program, or keep track of your names for you. If your program is organized, it’s because you organized it. That sounds hard, but it’s the point: every habit you build here, you build for real.

Modern languages are easier and more powerful. They come with tools that do a lot of this organizing for you. But someone who starts with one of them faces hundreds of features at once, and it’s easy to get lost. Without a foundation, all that power can be overwhelming. With one, each new feature makes sense, because you’ll recognize what it’s for: “Oh, this is just a subroutine with a name,” or “This is a record, like the ones I built with arrays.”

That’s where this book is headed. By the end, you’ll have built real programs, including a spending tracker that keeps its records on disk. Later, if you choose, you can take the same ideas to a modern language, and maybe turn that tracker into an app that runs on your own phone. A new language will be a new book. But the thinking comes with you, and the upgrade will feel less like starting over and more like getting better tools for work you already know how to do.

One last thing. You will make mistakes, lots of them. Every programmer does. In this book, a mistake is a discovery, not a failure. Each one teaches you something about how the machine works, and about how you think.

Let’s begin with something worth seeing.

A Maze in Two Lines

Before anything else, let’s make the C64 do something worth seeing.

Click the C64 screen. Type these two lines exactly as shown, and press RETURN at the end of each one. Keep Caps Lock off: type ordinary small letters, and the C64 will show them as capitals.

10 PRINT CHR$(205.5 + RND(1));
20 GOTO 10

Now type this and press RETURN:

RUN

A maze fills the screen, row after row, and never stops. Stop it and run it again, and you get a different maze. (There’s a surprise hiding in that word “random”, which Chapter 3 will let you discover for yourself.)

To stop it, press RUN/STOP. On a PC keyboard, that’s Esc. The C64 answers BREAK IN 10 (or 20) and READY.

Right now this probably looks like magic. It isn’t. Every piece has a meaning, and this book teaches you each one:

Piece What it does Taught in
10 and 20 Line numbers: the order of the steps Chapter 2
PRINT Puts something on the screen Chapter 1
; Keeps the next thing on the same row Chapter 1
RND(1) Picks a random number Chapter 3
CHR$( ) Turns a number into a character Chapter 4
GOTO 10 Jumps back to line 10 Chapter 9

When you finish Chapter 9, come back to this page. You’ll be able to explain every character in it.

Programmers sometimes squeeze this same maze into a single, very short line, as a kind of puzzle. It works, but it’s hard to read. This book always writes programs to be read, because a program you can read is a program you can fix.

How This Book Works

This book teaches you to program the Commodore 64. It also teaches something bigger: how to plan, how to keep things in order, and how to break a big job into small ones. Programmers call that organized thinking. The C64 is a good place to learn it, because its BASIC gives you almost no help. Any order in your program has to come from you.

What you need

  • An emulated C64. This book uses VICE, either on your computer or in the browser.
  • A paper notebook and a pencil. This is your programmer’s notebook. You will draw tables and maps in it before you type.
  • About thirty minutes. Every lesson fits in one sitting.

Reading the code

Anything shown on a dark blue screen like this is something to type:

PRINT "HELLO"

The little ↵ key at the end of the line means: press RETURN (Enter on a PC keyboard). The C64 does nothing with a line until you do. You don’t type the symbol itself.

How every lesson goes

Every lesson has the same seven steps, so you always know where you are:

  1. Goal: what you will be able to do by the end.
  2. Picture: a drawing of the idea.
  3. Try it: type something short and run it.
  4. Predict: change one thing, write down what you think will happen, then run it.
  5. Why it works: a short explanation.
  6. Organize it: one habit to add to your notebook.
  7. Exercises and quiz: practice, then five quick questions.

Getting a prediction wrong is not a failure. It’s how you find out what the computer really does. Error messages are normal too. Every chapter makes at least one on purpose.

Chapter 1: This Is a Variable

This chapter teaches two things. The first is the variable: how the C64 remembers numbers and words. The second is the C64’s rules about variables. Some of those rules are strange, and sooner or later one of them will trip you up. That happens to every C64 programmer.

You don’t need to memorize the rules now. Read them once, and remember that they’re here. Later, when a name doesn’t work or a number lands in the wrong place, come back to this chapter and check whether one of these rules explains it. Good programmers don’t know everything. They know where to look.

In this chapter you type commands and press RETURN, and the C64 does them right away. This is called direct mode. You won’t need line numbers until Chapter 2.

Lesson 1.1 — Boxes with labels

Goal: Put a number into the computer’s memory and get it back.

Picture: Picture a row of lockers in a hallway. Each locker has a name tag on the door, so you can find it again without opening every one. Each locker holds one thing. A labelled box like this is called a variable, and the computer’s memory is a very long row of them: thousands of boxes, side by side on one shelf.

If you play video games, you already know variables. Your experience points are a box labelled XP. Every time you finish a quest, the game opens that box, adds your reward, and puts the new total back.

     X           Y           K          <- labels
  +-----+     +-----+     +-----+
  | 100 |     |  0  |     |  0  |       <- what is inside
  +-----+     +-----+     +-----+
=======================================  <- the shelf

Try it. Type each line and press RETURN after it:

X = 100
PRINT X

The C64 answers 100. You put 100 into the box labelled X, then asked to see what was inside.

Predict. Before typing the next lines, write down what you think the C64 will show. Then try it.

X = X + 25
PRINT X
PRINT Y

Why it works. The = sign does not mean “is equal to” here. It means “put into.” X = X + 25 means: look in box X, add 25, and put the answer back in box X. So X now holds 125. Box Y was never filled, so it holds 0. On the C64, an empty number box always starts at 0.

That is exactly a quest reward: X = X + 25 is 25 more experience points.

Notice the space before each number. The C64 leaves room in front of every number for a minus sign, even when there isn’t one.

Want to know a secret? Type ? instead of the whole word PRINT, and you get the same thing, quicker.

Think of PRINT as a “what is?” command: you ask, and the C64 answers with what it is. So to ask “what is in X?”, you can type:

? X

To make the answer more meaningful, add a word after it:

? X "XP"

The C64 answers 125 XP. And if you use ? inside a program, LIST shows it spelled out as PRINT, because to the C64 they’re the same word.

Lesson 1.2 — Three kinds of boxes

Goal: Learn the three kinds of boxes, and prove they’re different.

Picture: Not every box can hold everything. A coin jar holds amounts you can count and add. An envelope holds a written message. You can’t add two messages together the way you add coins, and you can’t drop a message into a coin jar and expect it to count. The kind of thing a box can hold is called its data type.

Try it. The same letter can label three different boxes:

G = 250
G$ = "GEMS FOUND"
G% = 7
PRINT G;G$;G%

Predict what the last line will show before you press RETURN.

Why it works. The C64 answers 250 GEMS FOUND 7. There are three separate boxes here, all labelled G. The symbol at the end of a label is part of the label, and it tells the C64 what kind of box it is:

Label looks like Data type Holds Example
G, SC, X1 Number Any number, including decimals G = 12.5
G$, N$ Text (a string) Letters, digits and symbols, up to 255 of them, in quotes G$ = "GEMS FOUND"
G%, L% Whole number Whole numbers only, from −32768 to 32767 G% = 7

(Programmers in a wide variety of languages call whole numbers like these signed integers. More on that later in this book!)

Mixing words and boxes. The semicolon glues things together on one row, and it can glue words in quotes to boxes:

S = 12
PRINT "LEVEL";S;"CLEARED"
N$ = "NOVA"
PRINT N$;" SCORED";S;"STARS"

The C64 answers LEVEL 12 CLEARED and NOVA SCORED 12 STARS. Look closely at the spaces. A number brings its own space on each side, but words don’t. That’s why " SCORED" starts with a space inside its quotes: without it, you’d get NOVASCORED.

Predict, then try:

G = "GEMS"

The C64 answers ?TYPE MISMATCH ERROR. You tried to put a message into a number box. “Type mismatch” means the data type of the thing doesn’t match the data type of the box.

Prove it. A whole-number box is fussy. Try these:

G% = 9.99
? G%
G% = 50000

The first answer is 9. The whole-number box doesn’t round 9.99 up to 10: it simply drops everything after the decimal point. And 50000 gives ?ILLEGAL QUANTITY ERROR, because it’s too big to fit.

If the whole-number box is so fussy, why have it at all? It takes up less room in memory. That won’t matter for single boxes, but much later in this book you’ll build long rows of boxes, and there it adds up.

Lesson 1.3 — The two-letter trap

Goal: Learn the C64’s naming rules, including the strange ones.

Try it:

SHIELD = 80
SHOTS = 5
PRINT SHIELD

Predict before you run the last line. Most people expect 80.

Why. The C64 prints 5. It only reads the first two letters of a variable name. To the computer, SHIELD and SHOTS are both just SH: the same box. The second line quietly replaced the 80. Nothing warned you. Lesson 1.5 shows how to make sure it never happens to you.

Prove it. Ask the C64 what’s in all three names:

? SHIELD
? SHOTS
? SH

All three answer 5. Three names, one box.

Picture it this way: the C64 makes its labels with a label maker that can only print two letters. You ask for a label that says SHIELD, and the machine prints SH. Later you ask for SHOTS, and it prints SH again. Now the shelf has one box with the label SH, and both names lead to it.

Lesson 1.4 — Words the C64 has already claimed

Goal: Know which names are taken, so you can pick names without worrying.

Picture: Usernames in an online game. When you sign up, some names are already taken, and the game won’t let you have them. The C64 has about seventy words it has already claimed for itself: its commands and functions, like PRINT, GOTO and RUN. Programmers call them reserved words. Appendix E will list every one.

Predict. Will this work? Write down yes or no, then try it:

FORTUNE = 7

Why it fails. The C64 answers ?SYNTAX ERROR. When you press RETURN, the C64 reads your line looking for its own words, and it finds them even in the middle of a name. Hidden inside FORTUNE is FOR, as in FOR ... NEXT. The C64 sees FOR and can’t make sense of the rest.

The fix is easy: pick a name with no hidden word. LUCK = 7 works, and so does LK = 7.

Plenty of good names have a reserved word hiding inside:

Name Hidden word
FORTUNE FOR
DEFENSE DEF
VALUE VAL
TOKEN TO
DIFFICULTY IF
GOLD GO
POINTS INT
BONUS ON
SCORE OR
FRIEND END
STATUS ST
TIME TI

That list can make names feel like a minefield. They aren’t. Three facts turn it into a map:

  1. Inside quotes, nothing is reserved. PRINT "FORTUNE, DEFENSE AND VALUE" works perfectly. The C64 only hunts for its words outside quotes.
  2. You almost always find out right away. A name with a reserved word inside usually stops with an error the moment you press RETURN, so you fix it and move on. (There’s one sneaky exception, in the box below.)
  3. Two-letter names are safe, with just eight exceptions. The C64 only reads the first two letters of a name anyway, and only eight pairs are taken:
Taken pair Why
IF, ON, OR, TO, GO, FN They’re reserved words themselves
ST, TI They’re the C64’s own boxes (ST reports on disks and tapes; TI is its clock)

Any other two letters can never contain a reserved word. XP, HP, SH, LK, GM: all safe.

Here’s the sneaky one. A name like TITLE$ starts with TI, so to the C64 it’s TI$, the clock shown as hours, minutes and seconds. TITLE$ = "MY GAME" gives ?ILLEGAL QUANTITY ERROR, which at least warns you. But TITLE$ = "120000" gives no error at all: it quietly sets the clock to 12:00:00. Names that start with TI or ST are best avoided completely.

The rules for names, all in one place:

  • A name starts with a letter. After that, letters and digits are allowed.
  • Only the first two characters count, plus the $ or % that sets the data type.
  • A name must not contain a reserved word.
  • Two-letter names are always safe, except IF, ON, OR, TO, GO, FN, ST and TI.

Lesson 1.5 — Organize it: the variable dictionary

Goal: Start the habit that keeps every program in this book under control.

Because the C64 will not warn you when two names collide, you need a written list of every variable a program uses. This is your variable dictionary. Start a page in your programmer’s notebook like this (any paper notebook works, and until you have one, a sheet of paper will do):

Name Data type What it holds Example
X Number Experience points earned 125
N$ Text Player name NOVA
CS Number Cash, in dollars 75

Notebook rule 1: Before you use a new variable, write it in the dictionary. If its first two letters match one already there, or it’s one of the eight taken pairs, pick a different name. Short names are fine: the dictionary is where you write down what they mean.

When a box holds an amount, write its unit in the dictionary too. Is CS the cash in dollars or in cents? The number 75 means something very different in each. Later in this book, money is always stored in cents, and the dictionary is where you say so.

In 1999, a spacecraft called the Mars Climate Orbiter was lost at Mars. One team’s program measured thruster force in one unit, and another team’s program read those numbers as a different unit. Every number was right. Nobody had written down which units they were in.

Exercises

Second time through? Find a different answer that still works, then compare it with your first.

  1. Type and predict. Put the points you scored in two rounds of a game into two variables. Before printing their total, write down what it will be.
  2. Fix it. These commands don’t work. Find both problems, explain each in one sentence, and fix them: ARMOR = 30, then ENDURANCE = ARMOR * 2.
  3. Build it. Use three variables: the name of a place in a game you like, how many treasures are hidden there, and the name of the best treasure. Make the C64 print one sentence about it, mixing words and boxes the way Lesson 1.2 shows. Add all three to your variable dictionary first, with their data types.

Quiz

  1. After X = 4 and then X = X * 5, what does PRINT X show? (a) 4 (b) 9 (c) 20 (d) An error.
  2. After G% = 9.99, what does PRINT G% show? (a) 9.99 (b) 10 (c) 9 (d) An error.
  3. Which variable can hold the words GOOD JOB? (a) W (b) W% (c) W$ (d) Any of them.
  4. Which of these names is always safe? (a) DEFENSE (b) HP (c) TO (d) STARS.
  5. A program uses MAGIC and MANA. What goes wrong? (a) Nothing (b) They share one box, MA (c) MANA is a command (d) ?TYPE MISMATCH ERROR.

Chapter 2: Talking to the Computer

In Chapter 1, the C64 did each thing the moment you pressed RETURN. Now you’ll learn to give it a list of steps to do later, in order, as many times as you like. That list is a program.

Lesson 2.1 — Now or later

Goal: Tell the C64 to do something now, or save it for later.

Picture: A recipe card. Reading a recipe card doesn’t cook anything. You write the steps down first, then follow them when it’s time to cook. A video game level works the same way: the level is built in advance, and it plays out when you press Start.

Try it. Type this and press RETURN:

PRINT "GAME ON"

The C64 prints GAME ON straight away. That’s direct mode, the way you worked in Chapter 1.

Now type this, with a number in front, and press RETURN:

10 PRINT "GAME ON"

Predict. Before you look, write down what you think happened.

Why it works. Nothing was printed. The number at the start told the C64: don’t do this now, store it as line 10 of a program. That’s program mode. To follow the stored steps, type:

RUN

Now GAME ON appears. To see the stored program, type:

LIST

Lesson 2.2 — Lines know their places

Goal: Understand how line numbers keep a program in order.

Try it. Type these three lines in this exact order:

NEW
30 PRINT "FINISH LINE"
10 PRINT "START"
20 PRINT "HALFWAY"

NEW erases any program already stored, so you start clean.

Predict. You typed 30, then 10, then 20. What order will LIST show? What will RUN print? Write both down, then try them.

Why it works. The C64 files every line by its number, no matter what order you typed it in, like index cards sorted in a box:

  You typed:            The C64 keeps:
  30 PRINT "FINISH LINE"      10 PRINT "START"
  10 PRINT "START"        ->  20 PRINT "HALFWAY"
  20 PRINT "HALFWAY"          30 PRINT "FINISH LINE"

RUN always starts at the lowest number and works upward.

PRINT on its own, with nothing after it, prints an empty line. It’s the easy way to put a gap between lines of output, so a screen doesn’t look crowded.

Notice the gaps: 10, 20, 30, not 1, 2, 3. If you later need a step between START and HALFWAY, there’s room for it:

15 PRINT "QUARTER WAY"

LIST it and see where it went. Line numbers can be anything from 0 to 63999, so there’s plenty of room.

Some later versions of BASIC have a command that renumbers a whole program for you. The C64’s BASIC doesn’t. If you number by ones and run out of room, you have to retype lines. Numbering by tens is how C64 programmers avoid that.

Lesson 2.3 — Changing your mind

Goal: Replace, remove, and look at parts of a program.

Try it. With the four-line program from Lesson 2.2 still stored, type:

20 PRINT "HALFWAY THERE!"

Predict, then LIST it.

Why it works. A line with a number that already exists replaces the old line. The C64 keeps only one line 20.

Now type just the number, and press RETURN:

15

LIST again. Line 15 is gone. A line number with nothing after it removes that line.

When programs get long, you won’t want to see all of it at once. LIST can show part of a program:

You type The C64 shows
LIST Every line
LIST 20 Only line 20
LIST 10-20 Lines 10 through 20
LIST -20 Everything up to line 20
LIST 20- Line 20 and everything after it

RUN can start partway through, too: RUN 20 starts the program at line 20 instead of at the beginning.

And NEW erases the whole program. There’s no undo, so be sure before you use it.

Lesson 2.4 — Fixing a line on the screen

Goal: Fix a mistake without retyping the whole line.

Picture: You might think of the C64’s screen as a web form: you type in a box, then press Submit. It is, with one twist. The whole screen is the form, and every line on it has its own invisible Submit button. RETURN submits whichever line the cursor is on, not just the one you typed last.

Try it. Type this program, mistake included:

NEW
10 PRINT "TODAY'S TARGET:"
20 PRITN "500 POINTS"
30 PRINT "LET'S GO"
RUN

The C64 prints the first line, then stops with ?SYNTAX ERROR IN 20. Helpfully, it tells you which line has the problem. (Yes, the C64 really does print two spaces before the word ERROR.)

Why it works. PRITN isn’t a word the C64 knows: the last two letters are swapped. You could fix it by retyping all of line 20. But there’s a faster way, because the C64 lets you edit anything on the screen:

  1. Type LIST so line 20 is on the screen.
  2. Use the arrow keys to move the cursor up to line 20, and right until it’s on the T of PRITN.
  3. Type NT. Each letter you type replaces the one under the cursor, so TN becomes NT, and the line reads 20 PRINT "500 POINTS".
  4. Press RETURN while the cursor is anywhere on that line. That’s the line’s Submit button.

When you press RETURN, the C64 reads the whole line from the screen and stores it, exactly as if you had typed it fresh. LIST and RUN to check.

Making room. Typing over only replaces letters. When a letter is missing, you need room for it. Put the cursor where the missing letter belongs and press SHIFT + INST/DEL. That’s INSERT: everything from the cursor onward slides one place to the right, leaving a space. Type the missing letter into the gap, then press RETURN. On a PC keyboard, use the Insert key, or Shift + Backspace.

For example, if line 20 said 20 PRIT "500 POINTS", you’d put the cursor on the T, press INSERT once, and type N.

On the course site’s C64 page, holding Shift and clicking on the C64 screen moves the cursor straight to where you clicked, instead of using the arrow keys.

To clear the screen, hold SHIFT and press CLR/HOME. On a PC keyboard, that’s Shift + Home. (On many laptops, Home is Fn + Left Arrow, so it’s Shift + Fn + Left Arrow. The course site’s C64 page also has a Clear screen button right under the screen.) CLR/HOME without SHIFT just moves the cursor to the top left corner, without erasing anything.

Clearing the screen never touches your program: type LIST and it’s all still there. (If you’ve used other versions of BASIC, you might reach for CLS. The C64 doesn’t have it.)

Here’s how C64 programmers clear the screen from inside a program. Type a line up to the opening quote, then press SHIFT + CLR/HOME:

10 PRINT "{clr}ROUND 1"

Inside quotes, SHIFT + CLR/HOME doesn’t clear anything. Instead, it types the clear-screen code into your text, and the C64 shows it as a reversed heart. When the program runs, PRINT sends that code, the screen clears, and then ROUND 1 appears. This book writes the reversed heart as {clr}, because a heart is hard to print on paper.

A program line can fill two rows of the screen, but keep it shorter than 80 characters. When you type the 80th character, the cursor jumps down to a fresh row, and pressing RETURN then enters that empty row instead of your line, so your line is never stored. Long lines are also hard to read, so this book keeps them short.

Lesson 2.5 — Organize it: plan, then number

Goal: Start every program on paper, not on the keyboard.

A program is a list of steps in order. Before you type, write the steps in your notebook in plain words, one per line, the way you’d write a recipe. Then give each step a line number, counting by tens.

Step in plain words Line
Show a title 10
Show today’s goal 20
Show a cheer for reaching it 30

Now the typing is just copying, and the thinking is already done.

Notebook rule 2: Plan the steps on paper first, in order. Number the lines by tens, so there’s always room to add a step later.

Exercises

Second time through? Find a different answer that still works, then compare it with your first.

  1. Predict the order. Type NEW, then these lines in this order: 30 PRINT "BLUE", 10 PRINT "RED", 40 PRINT "VIOLET", 20 PRINT "GREEN". Before typing LIST and RUN, write down what each will show.
  2. Fix it two ways. Type the TODAY’S TARGET program from Lesson 2.4. Fix line 20 once by retyping the whole line, then break it again and fix it with the screen editor. Which way was faster?
  3. Build it. Plan a short “game over” screen on paper: a title, your final score, and a message, one per line, using variables from your variable dictionary. Number the lines by tens, type it, and run it. Then add a new line between the score and the message without retyping anything else.

Quiz

  1. You type 20 PRINT "SAVED" and press RETURN. What happens? (a) SAVED appears (b) The line is stored and nothing is printed (c) ?SYNTAX ERROR (d) The program runs.
  2. You type lines 60, then 30, then 50. What does LIST show first? (a) Line 60 (b) Line 50 (c) Whichever you typed last (d) Line 30.
  3. What does typing 30 by itself and pressing RETURN do? (a) Removes line 30 (b) Runs line 30 (c) Lists line 30 (d) Nothing.
  4. Why number lines 10, 20, 30 instead of 1, 2, 3? (a) It runs faster (b) The C64 requires it (c) It leaves room to add lines in between (d) It saves memory.
  5. Which command shows only lines 20 through 40? (a) LIST 20-40 (b) RUN 20 (c) LIST 40 (d) LIST -20.
